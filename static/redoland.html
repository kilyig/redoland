Working with Redoland

This web UI is read-only — it shows transcripts and stats and lets you Start / Pause a branch. Everything that changes a world — creating it, forking a worldline, injecting an event — is done from the command line, which is currently the only tool for that.

The CLI is built to be driven by an AI agent: every command is self-documenting, so you can hand the agent a goal and let it run the commands for you — that's the intended workflow. You can of course run the commands yourself as well. Run from the repo root with the project venv:

python -m redoland <command> -h — prints the mental model and per-command help (the inject schema and a worked example included).

Core commands

initcreate a new village — --premise "…" sets the stage
runadvance a branch forward (one commit per agent action)
timelineper-action commit history — these are the fork points
forkbranch a new worldline from any action
injectinject an event (a state change + public explanation)
diffcompare two branch / year snapshots
state · metricsliving roster + each agent's stats, or full JSON metrics
servethis read-only web UI

The mental model

A run is a village = its own git repo. Every agent action is a commit; a worldline is a git branch. Rewind to any moment, change something, run it forward, and compare how history diverges — that's the whole point.
